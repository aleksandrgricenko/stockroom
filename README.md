# Stockroom

Stockroom — веб-приложение для локальной демонстрации складского учёта. Сотрудник принимает поставки партиями, фиксирует причины брака, выдаёт товары и сверяет остатки с журналом движений. Все поставщики, товары и документы в демоданных вымышлены.

Стек — TypeScript, React, Vite, Node.js 24, Express 5 и PostgreSQL 17. Один сервер обслуживает API и собранный интерфейс.

## Запуск через Docker Compose

Из каталога проекта выполните:

```sh
docker compose up --build -d
docker compose ps
```

Откройте [Stockroom на localhost:3000](http://127.0.0.1:3000). При первом запуске PostgreSQL создаёт таблицы и загружает демоданные. Порты приложения и PostgreSQL привязаны к loopback. Данные сохраняются в томе между запусками.

```sh
docker compose down
```

Чтобы начать демо заново, выполните `docker compose down -v`, затем `docker compose up --build -d`. Ключ `-v` удаляет том вместе со всеми введёнными данными этого проекта.

## Запуск для разработки

Понадобятся Node.js 24 с npm и PostgreSQL 17. Для запуска только базы через Compose:

```sh
docker compose up -d --wait db
npm ci
```

Скопируйте `.env.example` в `.env` (`cp .env.example .env` или `Copy-Item .env.example .env` в PowerShell). Для отдельного экземпляра PostgreSQL создайте пустую базу, выполните в ней `db/001-init.sql` и `db/002-demo.sql`, затем укажите свой адрес в `DATABASE_URL` и `TEST_DATABASE_URL`.

```sh
npm run dev
```

Откройте [127.0.0.1:3000](http://127.0.0.1:3000). Для проверки собранного приложения остановите сервер разработки, выполните `npm run build` и `npm start`. Если уже работает контейнер `app`, освободите его порт командой `docker compose stop app` или задайте другой `PORT` в `.env`.

## Демонстрационный сценарий

На чистых демоданных у SKU `BX-210` нулевой остаток, а в поставке **ПСТ-1048** ожидается 10 коробок.

1. В «Поставках» найдите **ПСТ-1048** по номеру или поставщику «Северная Упаковка». Откройте карточку.
2. В первой партии укажите **6** принятых и **1** отклонённую единицу. Введите причину «Смята коробка» и сохраните. Статус станет «Частично обработана», останется обработать **3** единицы. В «Остатках» у `BX-210` будет **6** шт.
3. Вернитесь к поставке и примите ещё **3** единицы. Поставка получит статус «Обработана». Всего принято **9**, отклонена **1** единица, остаток на складе **9** шт.
4. В «Остатках» найдите `BX-210`, нажмите «Выдать» и оформите выдачу **4** шт. с основанием «Заявка Р-018». Остаток станет **5** шт.
5. Попробуйте выдать **6** шт. Сервер сообщит, что доступно 5 шт. Остаток и журнал сохранят прежние значения.
6. Откройте «История» у `BX-210`. Увидите два прихода **+6** и **+3**, выдачу **−4** и основания. По номеру поставки можно вернуться к её карточке и увидеть причину отклонения.

## Тесты

```sh
npm test
npm run typecheck
npm run test:integration
npx playwright install chromium
npm run test:e2e
```

Модульные тесты проверяют статусы, целые количества и обязательную причину брака. Интеграционные тесты обращаются к реальному HTTP API и PostgreSQL, включая откат второй строки приёмки, повторы и конкуренцию. Браузерный тест собирает интерфейс и запускает свой сервер. Для уже установленного Chromium можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE`.

Оба набора тестов с PostgreSQL требуют `TEST_DATABASE_URL` и право создавать схемы в указанной базе. Каждый тест загружает чистые демоданные в отдельную временную схему и удаляет её при штатном завершении. Публичная схема с данными локального приложения при этом сохраняется.

## Ограничения

Проект рассчитан на локальную демонстрацию. В нём нет авторизации, интеграций, редактора справочников и документов, возвратов и инвентаризаций. Поиск в списках поставок и остатков выполняется в браузере, журнал рассчитан на небольшое число записей. SQL-файлы инициализируют чистую базу. Последующие миграции схемы не предусмотрены. Учётные данные в примере предназначены для локальной базы.
